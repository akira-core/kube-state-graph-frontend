## Why

On a large cluster the Sankey (and to a lesser degree the Graph) is requested for the whole estate the moment a control changes, and the resulting body is big enough that layout and draw stall the browser. Every request-shaping control today is Grafana-shaped — change it and the request goes out — so an operator narrowing a scope pays for every intermediate state, cannot stop a request that is already too big, and on the Sankey cannot even start narrowed because the root selector is optional and enumerates from a body that has to be drawn first. Two smaller defects surfaced while looking at this: the nav bar's time range snaps back to its previous value (confirmed in the browser: selecting `1h` writes the URL three times within 25 ms and ends on `24h`, so the 1h request is followed by a 24h one and the control reverts), and the Sankey's derived `application` / `namespace` cards carry a status border although nothing in the backend can ever raise an alert on them.

## What Changes

- **Explicit Query and Cancel on both pages.** Filter / scope controls (and the nav bar's time range) edit a **draft**; nothing is requested until the operator presses **Query**. While a request is in flight the same control offers **Cancel**, which aborts the request and keeps the last drawn data. The URL carries the **applied** scope, written when Query commits, so a shared link still names exactly what was drawn. **BREAKING** for the current contract: mounting a page never fires a request on its own, even when the URL carries a complete scope — a deep link, a refresh and a route switch all prefill the draft and wait for Query. Reload and auto-refresh re-run the applied query and are unavailable until a first Query has been committed on that mount. Demo mode is exempt (there is no request to gate; fixtures render on mount as today).
- **Sankey root becomes required and multi-valued.** No storage-graph request is issued until `az`, `env` and **at least one** root are present; the root value control becomes a **multi-select** dropdown so several values of one kind can be committed at once (kinds may still be mixed, intersection semantics unchanged). Because a required root can no longer be enumerated from a drawn body, the candidates come from `endpoints.labelValues` where that store can answer — `node` from `kube_pod_info`'s `node` label, `pod` as `<namespace>/<pod>` from `kube_pod_info{namespace="…"}` scoped to the selected namespace narrowing — and from typed custom values for the storage-side kinds (`ontap_cluster` / `aggr` / `svm`), with the drawn body still contributing once a query has run. **BREAKING**: "no root = whole estate" stops being a valid request state.
- **Top-K pods, client-side, default 10.** A **Top pods** control on the Sankey scope bar keeps only the K pods with the highest total flow in the current mode (default `10`), dropping the pods below the cut and any `pvc` / `svm` / `aggr` / `netapp-node` no longer on a path to a kept pod. It is applied on the frontend to the normalized body, after the request, before derivation; hop weights stay exactly as the backend gave them, so an upstream ribbon may carry more than the kept downstream shows, and the summary states how many pods are hidden. The control is **unavailable (and not applied) while any `pod` root is present** — naming pods and ranking them are mutually exclusive.
- **`KSG_AZ_LABEL` / `KSG_ENV_LABEL` on the front door**, mirroring the backend's flags of the same name. The container's metrics proxy rewrites the label-values path for the two logical dimensions — `/metrics-api/api/v1/label/az/values` → `<target>/api/v1/label/<KSG_AZ_LABEL>/values` (and `env` alike) — so an estate whose external labels are named differently still populates the `az` / `env` controls. The SPA keeps sending the logical names and the backend keeps taking `?az=` / `?env=`, exactly as its own `--az-label` / `--env-label` contract says. The variables are validated as PromQL label names and required to differ; an invalid value stops the container before serving, like a malformed proxy target.
- **Derived Sankey containers lose the status border.** The `application` and `namespace` cards (and their summary-table dot and tooltip status item) present no status: they are synthesised columns with no alert, health or readiness signal of their own. The `Node` layout's wrapper keeps its fold, because a Kubernetes node is a real node with a status.
- **Fix the time-range revert.** `from` / `to` get a single writer: the page's Query commit writes the whole canonical query string (scope plus time) in one replace, and the shell's time-range hook stops rewriting `range` from a URL it has itself just written. The draft / applied split makes this structural rather than a patch.

## Capabilities

### New Capabilities

- `explicit-query`: the draft / applied model shared by both pages — the Query and Cancel controls, what counts as draft input (filters, projection, Sankey scope, time range), commit semantics (URL replace, then fetch), abort semantics, the no-auto-run-on-mount rule, how Reload and auto-refresh relate to the applied query, and the demo-mode exemption.

### Modified Capabilities

- `graph-filters`: "Changing any filter control MUST refetch" is withdrawn in favour of `explicit-query`; the filter bar gains the Query / Cancel control; the URL is the applied scope rather than the live selection; Clear resets the draft only. The label-values source additionally enumerates `node` and namespace-scoped `pod` for the Sankey's root candidates (still `kube_pod_info`, still through `endpoints.labelValues`).
- `graph-data-source`: request assembly is keyed on the applied selection, not on control state; the storage-graph fetch requires `az`, `env` and ≥1 root; loading / error / cancelled state propagation gains the cancelled outcome; "Reload and auto-refresh" operate on the applied query and are inert before the first commit.
- `storage-flow-sankey`: root selector becomes required and multi-valued with the new candidate sources; "No root is a valid state" is withdrawn; the Top pods control and its client-side projection are specified as the one sanctioned client-side narrowing, with the weight-imbalance and hidden-count rules; derived `application` / `namespace` cards keep the neutral border; Query / Cancel sit on the scope bar.
- `app-shell`: the view time range is a draft input committed by Query (URL `from` / `to` and local storage are written on commit); "Page-owned data lifecycle" no longer fetches on mount; "Reload action and status indicator" gains the in-flight Cancel affordance, the cancelled state, and unavailability until a first commit; the single-writer rule for the query string.
- `container-deployment`: the metrics proxy honours `KSG_AZ_LABEL` / `KSG_ENV_LABEL` (validation, rewrite, exit-on-invalid, documentation in `deploy/README.md` and the commented env in `deployment.yaml`).

## Impact

- **Frontend**: `src/features/graph-data/hooks/useGraphLoader.ts` (trigger model: explicit run / cancel instead of a `requestKey` effect), `src/features/app-shell/{GraphPage,SankeyPage,useUrlScope,useViewTimeRange,NavBar,ShellFrame}.tsx` (draft state, single URL writer, Query / Cancel wiring, status indicator), `src/features/graph-filters/{FilterBar,labelValues,useFilterOptions}` (Query control, `node` / scoped `pod` enumeration), `src/features/storage-flow-sankey/{SankeyScopeBar,SankeyView,SankeySummary,deriveSankey,sankeyUrlScope,useSankeyQuery}` (required multi-select roots, Top pods projection, neutral derived cards), the shared dropdown (multi-select root value with custom values). Unit and e2e suites for every requirement above; the Sankey performance fixture gains a Top-pods case.
- **Container**: `docker/entrypoint.sh` (two new validated variables and the per-dimension rewrite locations), container tests, `deploy/README.md`, `deploy/deployment.yaml`, `README.md`. The Vite dev proxy does not front `/metrics-api/`, so the rename is exercised at container level only.
- **Backend**: no change. `/v1/storage-graph` and `/v1/graph` keep their parameters; top-K is client-side by decision, so the backend never learns of it. A backend enumeration endpoint for storage-side roots would remove the "custom value only" limitation and is a candidate follow-up in `kube-state-graph`.
- **Demo repository**: the demo replaces the front door's `nginx.conf` wholesale, so it does not inherit the `KSG_AZ_LABEL` / `KSG_ENV_LABEL` locations; its `verify.sh` §10 assumptions (a request fires on page load; roots optional) will need a follow-up there once this merges.
- **Specs withdrawn**: the scenarios "Projection switch sends prune", "Pill overflow summary … the graph request updates immediately", "First request only once az / env are both present" (auto-fire), "A single candidate value is auto-preselected … immediately issues one request", "Deep link carries the estate … immediately issues one request", "No root is a valid state", and "A container borders by the worst status it hides" (for `application` / `namespace`) all change meaning and are rewritten in the delta specs.
