## Why

An operator who sees one switch interface's counter jump has no view here that answers "where did that traffic go, or where did it come from". The `sankey-panel` repository answers exactly that: a conserved Sankey over network-switch interface counters that walks from an investigated interface hop by hop — through switches, Kubernetes nodes, pods and their namespaces, or down to a host and the clients behind a port — drawing the delta in bits per second (Δbps) as ribbons and everything it did not follow as an explicit "other in" / "other out" residual, so that every hop balances. It is a separate React application with its own fetch, URL handling, zoom, tooltip, keyboard and CSS, all of which this repository already has under `storage-flow-sankey` and `app-shell`. Running two SPAs side by side would leave the operator switching tabs between two views of the same estate, and leave this repository maintaining two copies of every presentation primitive.

## What Changes

- **A `Network` category with two views.** The nav bar becomes two levels: category `Storage | Network` × view `Graph | Sankey`. The existing `/graph` and `/sankey` are the Storage category; `/network/graph` and `/network/sankey` are the Network category, served by one page component that holds one loader and one payload, so switching between the Network views issues no request. `/network` redirects to `/network/graph` keeping the query; an unknown view is the not-found page.
- **A network trace data source.** New optional runtime config key `endpoints.trace`; the request is `GET <trace>?hostname&from_ts&to_ts&max_hops&top_n&threshold&track_dir` with all seven parameters always explicit and the two timestamps in epoch **milliseconds**. The response is the same cytoscape-style wire body the other endpoints use, extended by four network fields (`metrics.delta_bps`, node `investigation`, `clients`, `other_in_bps` / `other_out_bps`), and it goes through the same `normalizeGraph` boundary, which learns those four fields additively; existing payloads normalize byte-identically.
- **Network scope controls.** Under `/network/*` the scope is the trace query: `hostname` (required; free text plus the switches of the last response as candidates), `max_hops` (7), `top_n` (3), `threshold` (10 %), `track_dir` (`source` | `destination`), with the nav bar's view time range as `from_ts` / `to_ts`. The draft holds raw strings: a missing URL value is the default, an invalid value is refused with a message and never silently rewritten. A `Min Δ` display threshold (`min_bps`) sits on the Sankey view's control bar and is written to the URL.
- **The full network Sankey.** Hop boxes with interface slot labels, "other in" / "other out" residuals filled by the per-hop balance, the anchor card for the investigated interface, trace-stop leaf cards with a clients table, owner aggregation cards with metered ribbons or unmetered ownership lines, derived pod → application → namespace cards, same-column (lateral) and backward ribbons with cycle breaking, the `Flat | Node` layout with Kubernetes-node wrappers, the display threshold folding hidden amounts into residuals, hover path highlighting, tooltips, zoom / fit / 1:1 / focus with keyboard shortcuts, a legend, a numeric summary, and Locate from a card into `/network/graph`.
- **Network Graph view.** The cytoscape `GraphView` draws the same payload; the `host` node kind and the `network-flow` edge type are registered (icon, category, colour, taxi routing, a Δ row in the hover tooltip).
- **One presentation infrastructure.** The zoom / pan viewport, control bar, keyboard handling, tooltip positioning, SVG host, box card and wrapper primitives, ribbon geometry, status legend and container sizing hooks are **moved** out of `storage-flow-sankey` into a shared `sankey-canvas` module that both Sankey views import. Only the network-specific domain logic — hop classification, edge aggregation and threshold filtering, residuals, anchor / leaf / owner / derived cards, column ordering and cycle breaking, lateral and backward ribbon paths, hover paths, tooltip text — is ported from `sankey-panel`. Its fetch, URL, zoom, tooltip, focus, CSS files, colour palette and class names are not brought over; the network cards take the look of the existing `SankeyCard` and the theme's tokens.
- **A third demo fixture** (`public/demo/trace.json`, generated from `src/shared/fixtures/showcaseTrace.ts`) so demo mode and the e2e suite exercise the whole path without a backend.

## Capabilities

### New Capabilities

- `network-trace`: the Network category's Sankey view — input and fetch parameters, scope controls and validation, hostname candidates, trace direction, hop boxes and slot labels, residuals and per-hop conservation, the anchor card, leaf / trace-stop cards with clients, owner aggregation, derived pod → application → namespace cards, column assignment with tier locking and cycle breaking, the `Flat | Node` layout, the `Min Δ` display threshold, legend, tooltips, hover path, Locate to `/network/graph`, empty states, formatting, theme and performance bounds.
- `sankey-canvas`: the shared presentation contract both Sankey views MUST use — SVG host and viewport transform, zoom / pan / fit / 1:1, control bar, keyboard shortcuts, tooltip positioning, box card and wrapper primitives, ribbon geometry and thickness scale, status legend, container size and opening viewport — with the guarantee that the storage view's output is unchanged by the extraction.

### Modified Capabilities

- `app-shell`: two-level navigation (category × view); the `/network`, `/network/:view` routes and the not-found rule for an unknown view; one page and one loader across the two Network views (0 requests on a view switch, payload retained); tab title; focus mode on the Network Sankey; Reload availability and auto-refresh for the trace source.
- `runtime-config`: `endpoints.trace` as an optional endpoint whose absence disables only the Network fetch.
- `graph-data-source`: trace request assembly (seven explicit parameters, millisecond timestamps, resolved at send time); normalize learns `delta_bps` → `deltaBps` on the I/O metrics family, node `investigation`, `clients`, `other_in_bps` / `other_out_bps`, reporting malformed values as error entries while keeping the node; existing payloads normalize byte-identically.
- `graph-view`: the `host` node kind and the `network-flow` edge type are registered in every kind / edge-type table (icon, category, colour, endpoints, taxi routing) and the hover tooltip shows a Δ row when an edge carries `deltaBps`.
- `storage-flow-sankey`: the zoom / pan, control bar, keyboard, tooltip, box card, wrapper, ribbon geometry and sizing requirements are now satisfied by the shared `sankey-canvas` module; the observable behaviour and rendered SVG are unchanged.
- `dev-environment`: a third typed fixture `SHOWCASE_TRACE` and its generated `public/demo/trace.json`, covered by `fixture:build` / `fixture:check`, plus the `tests/network-trace.spec.ts` e2e spec.
- `container-deployment` (documentation only): `deploy/README.md` and `deploy/configmap.yaml` mention `endpoints.trace`; `docker/nginx.conf` is unchanged because the trace endpoint is reached through the existing `/api` proxy.
