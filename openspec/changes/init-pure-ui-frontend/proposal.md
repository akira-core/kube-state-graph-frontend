## Why

`kube-state-graph-panel` exists as a Grafana panel plugin; its UI is constrained by the panel boundary, the `@grafana/ui` theme, the panel options editor, indirect fetching through the Infinity datasource, and the plugin signing and Grafana version upgrade path. To add a Sankey view for storage throughput and gain full UI control over multiple views, routing and an own theme, the single-panel model is no longer suitable. This change establishes a standalone pure-frontend SPA in this repo: it keeps the cytoscape.js format contract of the kube-state-graph backend, ports the panel's entire UI feature set, and adds a Sankey view weighted by storage I/O metrics.

The backend has another endpoint born for this shape. `GET /v1/graph` is **workload-rooted**: its default projection keeps only the pods sitting on a connection edge, and its selectors address only Kubernetes. A storage operator asks the opposite question — "this filer / this aggregate is degraded; which claims, pods and Kubernetes nodes sit on it?" — so the backend provides `GET /v1/storage-graph`: required single-valued `az` / `env`, a root search that can start from either the storage side or the workload side, one extra `netapp-svm` layer, a fixed tier chain in the storage → workload direction, and flow weights that are **conserved per tier**. None of these can be derived from the body of `/v1/graph`. This change therefore has each of the two views go to its own endpoint.

## What Changes

- **Establish a standalone SPA project scaffold**: React + TypeScript + Vite, Node 22, with a lint / format / typecheck / unit test / e2e toolchain and git hooks. No `@grafana/*` dependency of any kind.
- **Fetch directly from the backend, with each of the two graph endpoints serving one view**: call `GET /v1/graph` (Graph view) and `GET /v1/storage-graph` (Sankey view) directly with `fetch`, along with the node detail sub-endpoints (`code_changes`, `config_changes`, `dashboard`) and the filter option sources (`/v1/edge-types` and Prometheus-compatible label values), replacing the Infinity datasource and `getDataSourceSrv()`. The two graph endpoints return the same cytoscape.js shape, so they share one set of wire types and one normalize boundary, but **fetching, state and failure are fully independent**; storage-graph is lazy — it is not issued before the user enters the Sankey view. Keep the fixture-driven demo mode (two fixtures, one per endpoint): a clean checkout renders the full graph without a backend.
- **Every URL is configurable via runtime config**: each backend endpoint (graph, storageGraph, labelValues, edgeTypes, code_changes, config_changes, dashboard) is configured independently; configuration is loaded at **runtime** (a `config.json` mounted at container start), not baked in at build time, so the same image can be deployed to different environments. `graph` is the only required endpoint in non-demo mode; when `storageGraph` is absent the Sankey view shows a not-configured explanation while the Graph view is entirely unaffected. Invalid configuration reports an explicit error and never silently falls back to demo mode.
- **Deploy as a container on Kubernetes**: produce a container image whose static assets are served by a lightweight web server (such as nginx); config is injected via a ConfigMap mount; provide Deployment / Service / ConfigMap manifests (or a Helm chart) and a health check endpoint.
- **Port the wire → internal model anti-corruption layer**: the `WireGraph` types, `normalizeGraph`, `ICON_SVG_BY_KIND` and other `src/shared/**` pure logic are ported from the panel with the Grafana coupling removed; the showcase fixture is the single fake data source shared by both sides.
- **Port the graph view in full** (cytoscape.js canvas), at feature parity with the panel:
  - Core rendering: fcose / dagre layouts, compound containers and collapse, kind → icon encoding, edge type coloring, dark / light theme, container size responsiveness, empty / loading / error states
  - Legend: kind / edge-type visibility toggles, container legend, collapse-aware kind list, side collapse
  - Interaction: hover tooltip, pinned card, single selection + focus fade, node detail panel (Application / Containers / change history / Dashboard button)
  - Graph search: miss fade, proxy hit, result list, locate
  - Pod-parent mode: switching between the `controller` / `node` compound topologies
  - Ingress visibility toggle: hiding the `ingress-gateway` node set and dashed styling
  - Switch-tier layout: reading the switch level from `labels.level` and applying layout constraints
  - Node-group compound: the `cluster > node group > node` containers synthesized on the panel side
- **Add a Sankey storage flow view driven by `GET /v1/storage-graph`**: rendered along the backend's five `storage-flow` tiers `netapp-node → netapp-aggr → netapp-svm → pvc → pod` (direction storage → workload) followed by two **derived** columns `application → namespace`, walked up each pod's `data.parent` chain with weights summed per direction from that pod's drawn inbound links (the backend's own instruction to a consumer that wants those levels). The Kubernetes node is never a column: a `Layout` switch (`Flat`, default / `Node`) instead wraps each pod inside its node under the `Node` layout, wrappers ordered by node name, unscheduled pods below; the switch is transient view state like the Graph's pod-parent mode and does not enter the URL. Backend-tier link weights are taken directly from each `storage-flow` edge's `read_bytes_per_sec` / `write_bytes_per_sec` — **the frontend sums nothing but the derived columns and never splits**, because the backend already guarantees per-tier conservation and has already split RWX claims evenly (marked with `labels.attribution="split"`). Read / write are distinguishable; edges without metrics are not drawn (absent ≠ 0). The visual vocabulary is box-card nodes with gradient ribbons on a shared scale, plus in-graph zoom / pan and focus mode. The view carries its own estate selector (`az` / `env` **required, single-valued**; the backend returns 400 for both missing and multiple values) and root search (`ontap_cluster` / `node` / `aggr` / `svm` / `pod`, startable from either side and mixable). The estate selector and the `cluster` / `namespace` narrowing are presented with **the same dropdown component** as the Graph filter bar; estate, root, narrowing and read / write mode sync to the URL query. Drawn with a mainstream charting framework, selected in design.
- **Multi-view app shell, with the two views as independent pages**: `/graph` and `/sankey` are each a route page (client-side routing), each holding **its own** data source, control bar and loading lifecycle; switching routes unmounts the previous page and mounts the new one (**switch = reset**), so reload and auto-refresh naturally act only on the current page. A page's **request scope and view time range are carried in the URL query** (the Grafana dashboard variable model): deep-linkable, shareable, restorable via browser Back / refresh, and the only snapshot mechanism — a static SPA has no backend to store snapshots, and a scope saved in browser local storage is invisible on the next visit. Only the nav bar, theme and view time range are shared across pages. Selection, collapse, viewport, search, legend collapse, pod-parent mode, the Sankey layout and other view state are page-owned transient state, discarded on leaving the route and never put in the URL.
- **Add a view time range**: replaces the time range the panel inherited from the Grafana dashboard. The nav bar offers relative windows (1h / 6h / 24h / 7d) and a custom absolute window; there are three consumers: the `start` / `end` of the two graph endpoints (both required, with no relative form, so they are resolved at the moment each request is sent — a frozen window eventually falls outside retention and returns an empty graph indistinguishable from a broken pipeline), and the node detail Dashboard query (`from_time` / `to_time`); clicking an alert's "Last occurred" sets it to that moment ±5 minutes. The selection is written both to the URL (`from` / `to`; relative form `now-6h` / `now`, absolute form Unix seconds) and to browser local storage: a URL value takes precedence, otherwise the locally saved value is used, otherwise `24h`; after the page mounts the URL **always** carries `from` / `to`, so a copied link is self-describing.
- **Add backend graph filtering (`graph-filters`)**: replaces the narrowing done by Grafana dashboard variables. The filter bar below the nav bar provides cluster / AZ / env / namespace / edge type and projection (`prune`) controls as **Grafana-style dropdowns** (the trigger shows the selection summary; expanded, a search + multi-select checkbox list + an `All` row, with custom values allowed — except for `edge_type`, where the backend returns 400 for unregistered values), sent to the backend as query parameters rather than applied on the frontend; the selection **syncs to the URL query, with parameter names mirroring the backend**; options are enumerated from the pod inventory's label values and the backend edge-type catalog.
- **Not ported** (Grafana-specific, no corresponding concept): `pod-list-variable-export`, `selected-pod-export`, the panel options editor, `PanelPlugin` registration. Former panel options (layout algorithm, detail endpoints, etc.) become app configuration or UI controls.

## Capabilities

### New Capabilities

- `app-shell`: SPA entry point, view routing (`/graph` / `/sankey` are each an **independent page; switching resets**), **URL query as the carrier of page scope and view time range** (deep link / share / browser history restore), theme tokens and dark / light switching, view time range (the shared source for the two graph endpoints and the Dashboard query), global layout (top nav + page-owned control bar + full-width view area), **page-owned data lifecycle** (fetch on mount, abort on unmount) and reload / auto-refresh acting only on the current page.
- `runtime-config`: the runtime config contract — all backend endpoint URLs (graph, storageGraph, labelValues, edgeTypes, code_changes, config_changes, dashboard), demo mode, default layout, etc.; load sources and precedence, schema validation, missing-value behavior (an absent `storageGraph` only disables Sankey fetching and does not affect Graph), configuration error presentation.
- `container-deployment`: container image (static assets + web server), ConfigMap → runtime config injection, Kubernetes manifests (Deployment / Service / ConfigMap), health check, SPA fallback routing.
- `dev-environment`: Vite + TypeScript project structure, Node 22, ESLint / Prettier, Vitest unit tests, Playwright e2e, git hooks, fixture build / drift check scripts.
- `graph-data-source`: request assembly and fetching for **the two graph endpoints** (time range + filter parameters for `GET /v1/graph`; required single-valued `az` / `env` + root + lazy rule for `GET /v1/storage-graph`), independent loading / error states for each, demo mode with two fixtures, and the `WireGraph` types and `normalizeGraph` boundary shared by both endpoints (node kinds including `netapp-svm`, edge types including `storage-flow` with its `labels.tier` / `labels.attribution`, the union of RED / storage I/O metrics, usage / health / ready_status / hardware / perf, alerts, controller aggregation, worstStatus) — ported from the panel's `graph-data-integration`, with the datasource / provisioning requirements removed.
- `graph-view`: cytoscape.js canvas rendering, layout algorithms, compound and collapse, icon encoding, edge coloring, status outline, legend and filtering, hover tooltip, pinned card, selection and focus fade, empty / error states — ported from the panel's `panel-rendering` and `node-icon-encoding`, with the Grafana theme / panel option requirements removed.
- `node-detail`: node detail panel content (attributes, Application / Containers, change history), detail sub-endpoint fetching, the Dashboard button's applicability determination / parameter assembly / URL prefetch — ported from the panel's `panel-rendering` node detail requirements and `node-dashboard-url`, with endpoint resolution changed to a runtime base URL.
- `graph-search`: search bar, hit determination, miss fade, proxy hit, result list, locate — ported from the panel's `graph-search`.
- `pod-parent-mode`: the `controller` / `node` mode switch control and the `applyPodParentMode` topology transform — ported from the panel's `pod-parent-mode`.
- `ingress-visibility-toggle`: ingress-gateway node set identification, hide toggle, dashed styling — ported from the panel's `ingress-visibility-toggle`.
- `switch-tier-layout`: switch level reading and layout constraints — ported from the panel's `switch-tier-layout`.
- `node-group-compound`: the node group containers synthesized on the panel side — ported from the panel's `node-group-compound`.
- `storage-flow-sankey`: deriving Sankey nodes and links from the `/v1/storage-graph` response (five backend tiers plus the derived `application` / `namespace` columns, direct use of backend weights with the derived sums as the only client-side arithmetic, read / write split, missing-value handling, presentation of no-flow roots), the `Flat` / `Node` layout switch (Kubernetes nodes as pod wrappers ordered by name; transient), the estate and root selectors (sharing the `graph-filters` dropdown contract; estate, root, narrowing and mode go into the URL query), Sankey rendering (box-card nodes and slots, gradient ribbons with on-ribbon values, column headers, namespace grouping color bars, an off-graph numeric summary), zoom / pan and focus mode for the graph area, hover highlighting, and interoperation with the Graph view (clicking a node jumps to the Graph and locates it, and gives a recognizable hint rather than failing silently when the target does not exist in the graph body).
- `graph-filters`: graph filtering sent to the backend — the **Grafana-style dropdown** control contract (trigger summary and pills, search, multi-select, `All`, custom values, keyboard operation; this contract is also shared by the Sankey estate selector), cluster / AZ / env / namespace / edge type and projection (`prune`), their query parameter mapping, **URL query sync** (deep link / refresh / Back restore, with parameter names mirroring the backend), option enumeration from pod inventory label values and the backend edge-type catalog, degradation when a source fails — replaces Grafana dashboard variables.

## Impact

- **New code**: the entire `src/` tree (feature-first structure, following the panel convention), `tests/`, `vite.config.ts`, `package.json` and other project configuration.
- **New dependencies** (candidates, finalized in design): `react`, `react-dom`, `vite`, `typescript`; `cytoscape`, `cytoscape-fcose`, `cytoscape-dagre`, `cytoscape-expand-collapse` (same as the panel); Sankey candidates — `d3-sankey` (layout) + React-drawn SVG, Apache ECharts (built-in sankey series), `@nivo/sankey`; a client-side router (such as `react-router`); positioning, focus and dismiss for the dropdown popover — `@radix-ui/react-popover`; testing `vitest`, `@playwright/test`.
- **External systems**: the kube-state-graph backend's `GET /v1/graph`, `GET /v1/storage-graph`, `/v1/edge-types` and detail sub-endpoints (`code_changes`, `config_changes`, `dashboard`), plus the Prometheus-compatible label-values API holding the pod inventory; every URL is specified by runtime config (CORS must allow the frontend origin, or it is handled by a web server reverse proxy / dev proxy). **No backend contract changes** — `/v1/storage-graph`, the `storage-flow` edge type, the `netapp-svm` node and the `data.hardware` / `data.perf` / `data.alerts` attributes are all existing backend capabilities (see backend change `add-netapp-storage-graph-api`); this change only consumes them. The Sankey → Graph Locate target is passed via router navigation state and does not go into the URL.
- **Deployment**: a Kubernetes cluster; add a `Dockerfile`, web server configuration and `deploy/` manifests; CI must build and push the image.
- **Relationship to the panel repo**: `src/shared/**` and each feature's pure logic are brought in by copy-porting (not a monorepo, not a package dependency); the two repos evolve independently thereafter. Fixtures must stay in sync with the backend contract, reusing the panel's `fixture:check` drift check mechanism.
- **Non-goals**: backend changes, Grafana integration, authentication / authorization, switching between multiple backend instances, Ingress / TLS configuration (provided by cluster operations).
